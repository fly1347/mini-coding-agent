# 实验结果

[English](en/evaluation.md)

2026-09-10，使用 `deepseek-v4-flash` 在本地工作区进行六次真实运行，观察从零开发、已有项目增量修改、预算停止与 Skill/MCP 接入。上下文策略为 Full History。

本页从原始运行记录和当时的外部复验结果提炼，公开仓库只保留总结，不分发原始 trace 或生成项目快照。数据是单次运行观察，不构成模型 benchmark，也不支持稳定成功率或策略优劣的统计结论。

## 任务与设置

**Job Tracker 0→1**：从空目录开发本地岗位投递记录 CLI，包含新增、查看、筛选、状态更新、详情、删除、SQLite 持久化、异常处理与自动化测试。只给功能与验收要求，目录结构、表结构、CLI 和实现顺序由 Agent 决定。

**增量开发**：在 V1 上增加 `company + job_id` 重复保护、CSV 导出与状态统计，`job_id` 为空时不启用重复保护。新需求与 V1 主动设计的全局 `job_id UNIQUE` 发生冲突，需要修改实现、迁移逻辑与测试。

**Skill + MCP**：在 slugify 修复任务中按需加载 test-repair Skill，通过 MCP 获得 CLI 与 subprocess 回归要求，观察扩展是否被实际使用。

首轮使用旧 `thinking=auto`，API 返回 reasoning tokens；后续显式 `enabled`。本轮没有 Thinking / Non-thinking 对照。0→1 两轮之间还修改了预算与长度截断恢复，不能把差异归因于单个因素。

## 外部复验与关键观察

| 运行 | 当时的外部复验 | 观察 |
|---|---|---|
| V1 初跑 | 59 项：58 PASS / 1 ERROR | 测试缺 `contextlib` import，尚未进入完整验证就停止 |
| V1 成功 | 54/54 PASS，Smoke PASS | 验证后修改源码，必须再次完整回归才能交付 |
| V2 250K | 54 项：5 ERROR，Smoke FAIL | 已调用的新方法尚未实现，属于中途截断 |
| V2 800K | 81 项：80 PASS / 1 FAIL，Smoke PASS | 旧测试仍要求全局 job_id 唯一，与新需求冲突 |
| V2 接力 | 97/97 PASS，Smoke PASS | 代码通过外部测试，但 Run 未完成最终交付 |
| Skill + MCP | 16/16 PASS | 加载方法、读取外部要求、失败修复与回归均发生 |

外部复验使用完整 `unittest`，Job Tracker 必要时执行 `tools/smoke_check.py`。这些数量是被开发项目的测试，不是 Mini Coding Agent 自身测试数量。

800K 与接力共用一个工作区，接力后源码已变化；81 项结果来自当时记录，不能使用接力后的代码当作该时点快照。接力是新开 Run 读取代码现场，不是恢复上一轮 Session。

### 0→1 验证闭环

```text
查看空目录 → 保存计划 → 创建项目 → 54 tests PASS → Smoke PASS
→ 再次修改源码 → 旧验证失效 → 54 tests PASS → finish
```

这次运行展示了代码门禁实际参与开发过程。Agent 也主动增加了需求外设计，后续变更时必须重新检查这些假设。

### 预算机制与上下文限制

旧输入预留曾估计约 56K，实际 API 输入约 13K，造成提前截断。分账与动态校准后，V2 250K 的停止原因为：剩余 Input 26,252，下一轮预计 36,941。

增量任务包含大量源码读取、编辑与测试输出，完整历史反复进入后续 Prompt。提高到 800K 后仍耗尽预算，说明上下文增长已成为本轮的主要限制；高缓存命中不能消除累计 Input 压力。

### 状态与代码事实

最后一轮接力仍是 `TOKEN_BUDGET`，尽管外部测试已全部通过。Harness 没有在预算内完成当前有效的最终验证与 `finish`，事后测试成功不能回写成 `SUCCESS`。

## 已验证与尚未回答

本轮观察到完整 0→1 开发闭环、已有项目需求冲突处理、真实失败反馈、验证失效重验、预算停止，以及 Skill/MCP 进入同一 Agent Loop。

没有比较不同模型，没有验证 Skill/MCP 是否提升质量或效率，也没有证明任何 Context Management 策略优于 Full History。重复运行、固定任务集和更强的独立验收需要另行设计。

Mini Coding Agent 自身另有 **46 项离线回归测试**，覆盖工作区边界、真实沙箱与 MCP、计划/验证门禁、预算与长度截断、Provider 与报告。它们使用可控模型回复，不冒充真实 LLM 运行，可按 [使用指南](usage.md) 复验。
