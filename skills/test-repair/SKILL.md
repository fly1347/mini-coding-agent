# 测试驱动修复

修改已有 Python 行为时，按以下步骤操作：

1. 阅读任务约定、相关实现和现有测试。
2. 保存简短开发计划，在修改前运行现有测试。
3. 阅读失败输出，区分断言不符、语法或导入错误、运行环境问题。
4. 补充覆盖缺失行为的回归用例，保留现有断言。
5. 按任务约定做必要的最小修改，不只迎合某个示例。
6. 需要时先重跑失败用例，再执行指定的完整验收命令。
7. 交付改动说明、真实测试证据和剩余限制。不得把失败说成通过。

文本规范化任务应考虑空输入、重复分隔符、首尾分隔符和明确支持的字符集，不自行增加需求。

本文件是按需加载的操作指导，不是可执行代码，也不能覆盖运行器的权限与门禁。
